- `--env REPLAY_PROFILE=1` adds `profile_us_per_frame` to `replay-result.txt` (which D3D11 call group the frame

  laptop `runtime/laptop-port/frametime2/NIER_CAPTURE/frame_220084953`, `frame_220097046`.
- Rules: one change per run. Every fix gets a gate that fails on the old DLL. A number without a run label is not
  evidence. Replay runs on the RX 6800 XT (`1002:73bf`); it drives no monitor. Ask the user before using the
  RX 9070 XT (`--gpu 1002:7550`), and before any laptop or game run.
- Replay limits: no vertex shaders (nothing is rasterised on the game side, so the game's own GPU cost is absent);
  captures hold mip 0 only and no draws under 128 indices; one static frame unless `--switch N` with two captures.

### E. Evidence added 2026-11-12 (replay, 6800 XT, 2,500 frames unless said)

- **P5, duplicates: none left.** Scene draws per capture 30632051 / 41686139: 2,028 / 1,074, of which the prepass rule
  already drops 778 / 449. Among the 1,250 / 625 kept, the same geometry (index buffer, index range, POSITION vertex
  buffer) is drawn more than once 334 / 79 times, but **zero** of those repeats share geometry *and* pixel shader *and*
  constant-buffer slices: they are the same mesh under different transforms/materials, i.e. real objects. Nothing to
  merge; a merge would be wrong. The prepass is what was worth removing, and it is removed.
- **P6, small meshes.** 49% / 52% of scene draws are under 1,000 triangles (median 966 / 947), i.e. by default they land
  in the merged BLAS the runtime rebuilds every frame. 30632051: `rtx.minPrimsInDynamicBLAS = 0` **29.3 fps** (was 25.1),
  readback 31.1 (was 36.8); `= 300` 27.0; `= 3000` 21.7. So promote everything; the merged bucket is the cost.
- **P7, switches.** `s2-soak-3063-2139` (two captures alternating every 300 frames, 60,000 frames): 43.4 fps median,
  game frame p50 6.4 ms, p99 84.8 ms, worst 202 ms (the switch frames), no crash, all frames presented.
- **S2, soak.** Same run: RSS 1.87-1.98 GB with no trend, meshes bounded at 1,835 (`built=102,213 evicted=99,129`: each
  switch evicts the other scene's meshes, which is the budget working, not a leak).
- **S4, exit hang.** Not reproduced under the replayer: it calls `TerminateProcess`, so the game's own exit path with
  our DLL is still unmeasured. Recorded as open with that reason.
- **S5, review findings (from the `reviewer` pass on the whole diff), and what was done:**
  - P1 "a redirected map can outlive its mapping": fixed. A leftover redirect is now flushed at the next `Map` of that
    resource, permitted or not, so no entry can be written into a later mapping. Not reproducible deterministically in
    the Wine mock (the teardown switch fires on an arbitrary redirect, so it does not land inside a double map), which
    is why the combined `teardown-twice` case passes before and after: the fix is defence in depth, the existing cases
    pin the behaviour.
  - P2 "`buffer_bytes` reads a buffer the game has mapped": fixed. A buffer with an outstanding redirect reports no
    bytes (the mirror is borrowed into the mapping), so nothing reads a mapped resource.
  - P2 "profiler counters raced": fixed. Atomics, and `rest` is clamped.
  - P2 "the probe's `FreeLibrary` runs the runtime's DllMain detach": fixed, the probe keeps the module loaded.
  - P2 "`SetDllDirectoryW` stays set": accepted, with a `shortcut:` note; `AddDllDirectory` would not help the shim's
    own bare-name load, which is the thing that fails.
  - P3 items: `substr(0, slash + 1)` for a drive root, the mock's failed-second-map branch writes through a pointer it
    owns, the mock releases its staging buffer, `NIER_REMIX_LIVE_PROFILE` added to the gates' `ENV_KEYS`.
  - Left alone, recorded: the camera's cached bytes are never re-read unless the buffer is invalidated (a write path we
    do not hook would leave a stale camera); the first redirect seeds unwritten bytes with zeros (legal for DISCARD).
