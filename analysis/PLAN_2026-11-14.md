# Plan 2026-11-14 — playable on the laptop

## 0. Scope and execution contract

Active implementation plan. This revision is a **planning deliverable**, not evidence that its implementation tasks
have run. It replaces the short track list; [the previous plan](PLAN_2026-11-13.md) remains the historical record.
Goal: retain the accepted camp rendering, recover missing world/effect features, and establish a usable laptop play
path with measured performance, correct HUD/menus and safe deployment.

During a **plan-editing or research request**, finish that requested deliverable and review it; do not launch the
implementation backlog. During an **execution request**, use this loop:

1. Inspect `git status`, the baseline, current task evidence, and resource availability. Preserve user changes;
   stop for unexpected/unrelated changes rather than resetting them.
2. Select the first ready task in the table below. A blocked substep does not block independent ready tasks.
3. Freeze a failing gate before changing behavior. Delegate bounded work; lead owns integration and acceptance.
4. Rerun gates, relevant regressions and the full suite; review the diff and preserve evidence. Advance status.
5. Continue immediately. A progress report is not a stopping point. If nothing is ready, report the exact external
   dependency and the smallest user action that unlocks it. Do not describe blocked or rejected work as done.

Statuses: `open`, `active`, `waiting: <dependency>`, `done`. Record completed substeps under a waiting task so they
are not repeated. An experiment's negative result can close its spike, **not** silently satisfy its parent feature.
A no-go or deferred feature needs a recorded disposition and user agreement before overall project completion.

**No commits or pushes without an explicit request.** The old short plan's automatic commit/push instruction was
wrong and is removed. Permissions, saves, remote machines and game installs remain protected by `AGENTS.md`.

### 1.2 Findings that change the original plan

- `Startup` returns `ALREADY_EXISTS` after our D3D9 device registration. Changing `StartupInfo` alone does not
  reconfigure the existing presenter. FG output belongs to Remix's presenter, not the copied frame.
- Native-scale play replaces the game's final target immediately before HUD sprites in
  `checks/remix_live.cpp` (`before_draw`); Present-hook HUD replay is not the only path. Laptop `hud=0` does not
  mean the game had no HUD. Every E1/P2 design must address this native handoff and fallback behavior.
- The old capture floor is 128 indices. Small particles/fullscreen passes are absent. Missing t27/t30 entries in
  `ps_textures` are expected for structured buffers; they do not prove absent effects. t13 can be scene depth.
- The effect-drop tally currently supplies invented blend/target values. Repair instrumentation before using that
  tally to choose a blend strategy. Effects can be alpha, additive, dithered opaque, distortion or postprocessing.
- Captured PS CB2 sun values differ: camp `(6,5.1,4.8)`, desert `(8,7.2,4.8)`, pond `(10,9,7)`.
  Desert/pond fog-color scalars observed: 2.937 / 5.753. Floats 24–26 also differ; their physical meaning is
  **unverified**. Do not label them sky/ambient without shader-use evidence.
- API `SKY` geometry is hidden in the inspected runtime path; D3D9 sky rasterization is not automatically applied
  to API meshes. A dome light is a candidate, not proof of a complete sky reconstruction.
- `dump_shader_decls.py` produces corrupt variable names for some cbuffers. Confirm RDEF record size and absolute
  versus relative offsets against DXBC bytes and disassembly before using its names as material classifications.
- The game has no general outdoor day/night cycle. W4 needs emissive lamps/interiors/effects, not a fictitious
  “night capture.” Hair tangent-texture support is not established by an API field's existence.
- Historical exit observation (superseded by process-level C2 monitoring): proxy shutdown does not call `remixapi_Shutdown`; the replayer launcher timed out and forced termination
  hides it. This does **not** prove where teardown hangs. A pre-exit dump cannot diagnose a later deadlock.
- A real save differed from an old backup. Steam Cloud is a hypothesis, not a demonstrated cause. Do not restore
  an old backup over potentially newer play progress or hard-code stale save hashes into a gate.
- `VISION.md` excludes `lsfg-vk`; its appearance in a research report is not authorization to add it. NVIDIA
  Smooth Motion is only an optional capability question for the user, not an assumed supported path.

### T1 — obtain calibrated same-scene truth

**Scope:** native handoff in `checks/remix_live.cpp`, existing screenshot/raw conversion helpers and mock HUD tests.

The game renders its own final target before we overwrite it. A tap before that quad is a candidate truth source,
not automatically the final display image. `shown.pixels` can be older than the game frame due to worker latency;
“same frame” requires IDs/timestamps/camera alignment, not just capturing both in one hook.

1. Gate an opt-in tap using known game/fake-runtime colors. Off means no allocations/copies/files and unchanged
   output. On captures before overwrite, handles row pitch/format, releases resources on resize/failure and emits
   game-frame ID, Remix-source ID, camera, dimensions, encoding and timestamps. Mutation: move tap after overwrite.
2. Decode `R11G11B10_FLOAT` with tested unsigned-float rules, including subnormals/nonfinite values. Preserve HDR
   data for analysis; do not clamp/gamma-fit away unknown color space. Reuse screenshot tools rather than inventing
   a second incompatible raw format.
3. Validate against an original-game final screenshot at a still camp camera, excluding HUD and controlling

## 5. Delegation and team workflow

Lead owns design, frozen gates, integration, hardware runs and acceptance. Workers never deploy, touch saves,
change frozen tests or accept their own work. Assign one writer per overlapping file set; particularly serialize
`remix_live.cpp`, `live_capture.h`, `live_scene.h`, capture wrappers and fake-runtime edits.

| Wave | Independent work packages | Join / acceptance |
| --- | --- | --- |
| A | scout: runtime/guard caller map; local-worker: bounded parser or packer task after lead gate; reviewer: safety design | A0/A1 receipts before live work |
| B | deploy worker: C3a; local-worker: terrain mips C3b; scout: effect/sky/water inventory from fixed inputs | lead reruns gates; core edits serialized |

`local-worker`; `laptop-worker` while desktop GPU is reserved, if laptop is not playing; low-risk text from

model overrides. Read workflow-authoring guidance when writing scripts.
